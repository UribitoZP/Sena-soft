Aplicativo Móvil

Dashboard administrativo de solo lectura para el Hotel Santa Ana. Desarrollado en Flutter, se conecta en tiempo real al aplicativo de escritorio mediante una API REST.

Importante: Esta app es de solo lectura y exclusiva para administradores. No permite crear, editar ni eliminar datos. Toda la gestión se realiza desde el aplicativo de escritorio.

Arquitectura actual — Modo de pruebas: Por el momento, el servidor REST que alimenta esta app corre dentro del mismo PC que tiene el aplicativo de escritorio. Esta configuración fue diseñada para pruebas de conexión y generación de evidencia académica.

Próximamente el sistema contará con un servidor dedicado (un equipo adaptado exclusivamente para este fin) que mantendrá el servidor REST activo de forma permanente e independiente del PC del administrador. Esto permitirá consultar los datos desde el móvil en cualquier momento, sin necesidad de que el escritorio esté abierto.

Requisitos

Requisito Detalle
Dispositivo Android 7.0 (API 24) o superior
Red Misma red WiFi o LAN que el PC con el aplicativo de escritorio
Aplicativo de escritorio Debe estar abierto y ejecutándose en el PC para que la app móvil tenga datos
Puerto El puerto 8080 del PC no debe estar bloqueado por el firewall

Instalación en el Dispositivo

Opción A — Instalar el APK directamente (Recomendada para usuarios finales)

  1. Copia el archivo app-debug.apk al dispositivo (vía USB, WhatsApp o Google Drive).
    Ubicación del APK: Aplicativo Movil/santa_ana_dashboard/build/app/outputs/flutter-apk/app-debug.apk
  2. En el celular, abre el archivo APK. Si aparece una advertencia de "fuente desconocida", ve a Ajustes → Seguridad → Instalar apps desconocidas y habilita el permiso para tu administrador de archivos.
  3. Toca Instalar y espera que finalice.
  4. Abre la app desde el cajón de aplicaciones.

Firewall de Windows: La primera vez que se levanta el servidor REST, Windows puede mostrar una alerta de firewall. Es necesario hacer clic en "Permitir acceso" para que el celular pueda conectarse.

Opción B — Compilar e instalar desde el código fuente (Para desarrolladores)

Requiere tener Flutter instalado en el PC.

# 1. Ir a la carpeta del proyecto Flutter
cd "Aplicativo Movil/santa_ana_dashboard"

# 2. Instalar dependencias
flutter pub get

# 3. Conectar el celular por USB con depuración USB activada

# 4. Verificar que el dispositivo es reconocido
flutter devices

# 5. Ejecutar en el dispositivo
flutter run -d <ID_DEL_DISPOSITIVO>

# O compilar el APK para distribuir
flutter build apk --debug

Configuración de la IP del servidor

La app necesita conocer la dirección IP del PC donde corre el aplicativo de escritorio. Esta se configura directamente desde la pantalla de login:

  1. Abre la app → en la pantalla de login toca "⚙ IP del servidor".
  2. Escribe la IP local del PC (ejemplo: 192.168.0.105).
  3. Para conocer la IP del PC: abre cmd y ejecuta ipconfig. Busca la dirección IPv4 de la red WiFi.
Escenario IP a usar
Emulador Android en el mismo PC 10.0.2.2 (valor por defecto)
Dispositivo físico en la misma red WiFi IP local del PC, ej: 192.168.0.105
Dispositivo físico por cable USB con ADB localhost o 127.0.0.1 con port forwarding

¿Cómo y por qué funciona así?

1. Diagrama de comunicación

┌─────────────────────────────────────────────────────────┐
│                    Red WiFi local                        │
│                                                         │
│  ┌──────────────────┐    HTTP/JSON     ┌─────────────┐  │
│  │  App Flutter     │ ◄──────────────► │  Escritorio │  │
│  │  (Android)       │  puerto 8080     │  Java Swing │  │
│  │                  │                  │  + SQLite   │  │
│  └──────────────────┘                  └─────────────┘  │
└─────────────────────────────────────────────────────────┘

El aplicativo de escritorio funciona como un servidor y cliente al mismo tiempo:

  • Como cliente: el personal del hotel lo usa para gestionar habitaciones y reservas.
  • Como servidor: expone la información en formato JSON a través del puerto 8080 para que el móvil la consulte.

2. Flujo de autenticación

Cuando el administrador ingresa su usuario y contraseña en la app móvil:

  1. La app envía una solicitud POST /auth/login con el usuario y la clave en formato JSON.
  2. El servidor Java verifica las credenciales contra la base de datos SQLite.
  3. Si son correctas, retorna el perfil del usuario incluyendo su rol.
  4. La app verifica que el rol sea "Administrador". Si no lo es, deniega el acceso aunque la clave sea correcta.
  5. Si todo está bien, navega al dashboard principal.
// Petición desde Flutter
POST http://192.168.0.105:8080/auth/login
Content-Type: application/json

{"usuario": "admin", "clave": "1234", "rol": ""}

// Respuesta del servidor Java
{
  "id": 1,
  "nombre": "Administrador Principal",
  "usuario": "admin",
  "rol": "Administrador"
}

3. Carga de datos en las vistas

Cada sección de la app carga sus datos de forma independiente usando FutureBuilder, que muestra un indicador de carga mientras espera la respuesta del servidor y luego renderiza la información:

Vista Endpoint que consume Datos que muestra
Inicio (Home) GET /stats % de ocupación, habitaciones por estado, reservas activas/completadas/canceladas
Habitaciones GET /habitaciones Listado de todas las habitaciones con tipo, precio y estado. Filtros por estado.
Reservas GET /reservas Listado de todas las reservas con cliente, documento, habitación, fechas y estado. Búsqueda y filtros.

4. Actualización de datos (Pull to Refresh)

La app no actualiza los datos automáticamente. Para ver los cambios más recientes realizados desde el escritorio, el usuario puede deslizar la pantalla hacia abajo (pull to refresh) en cualquier vista. Esto dispara una nueva petición al servidor y recarga la información.

5. Arquitectura Flutter — Patrón BLoC + ApiService

lib/
├── core/
│   ├── services/
│   │   └── api_service.dart      // Centraliza todas las llamadas HTTP
│   ├── theme/
│   │   └── app_theme.dart        // Colores y tipografía globales
│   └── constants/
│       └── app_strings.dart      // Textos de la interfaz
└── feature/
    └── home/
        └── presentation/
            ├── bloc/
            │   ├── bloc_bloc.dart    // Lógica: login, carga de datos
            │   ├── bloc_event.dart   // Acciones: LoginRequested, LoadDashboardData
            │   └── bloc_state.dart   // Estados: Loading, LoginSuccess, Failure
            └── views/
                ├── Login_view.dart         // Pantalla de login con campo de IP
                ├── dashboard_view.dart     // Navegación con barra inferior
                ├── home_view.dart          // Vista de estadísticas generales
                ├── habitaciones_view.dart  // Vista de habitaciones
                └── reservas_view.dart      // Vista de reservas

¿Por qué BLoC para el login y FutureBuilder para los datos?
El login necesita gestión de estado reactiva (loading → success/error) que afecta la navegación global, por eso usa BLoC. Las vistas de datos son independientes entre sí y solo necesitan cargar y mostrar información, por eso usan el más simple FutureBuilder directamente.

Solución de Problemas Comunes

Problema Causa probable Solución
La app muestra "Sin conexión al servidor" IP incorrecta o el escritorio no está abierto Verifica que el aplicativo de escritorio esté corriendo. Confirma la IP con ipconfig en cmd y actualízala en la pantalla de login.
"Acceso denegado" al ingresar Se intentó ingresar con cuenta de recepcionista Usar el usuario admin con contraseña 1234.
"Credenciales incorrectas" Usuario o contraseña erróneos Verificar usuario y contraseña. Las credenciales son las mismas que en el escritorio.
Las habitaciones/reservas no se cargan El servidor no responde o hubo un error de red Hacer pull to refresh (deslizar hacia abajo). Verificar que ambos dispositivos estén en la misma red WiFi.
El celular no aparece al ejecutar flutter devices Depuración USB no activada o no autorizada Activar Opciones de desarrollador y Depuración USB en el celular. Aceptar el diálogo de autorización que aparece al conectar el cable.
Los datos no reflejan los últimos cambios La app no se actualiza automáticamente Deslizar hacia abajo en la vista para recargar (pull to refresh).
