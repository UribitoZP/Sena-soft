Aplicativo Móvil

Dashboard Administrativo de Santa Ana (Desarrollado en Flutter)

1. Arquitectura de Software

El aplicativo móvil utiliza una arquitectura basada en **Clean Architecture** adaptada para Flutter, empleando **Bloc (Business Logic Component)** como patrón de gestión de estado principal.

lib/
├── core/             // Elementos compartidos (Themes, Widgets, Constants)
├── feature/
│   └── home/         // Módulo principal del Dashboard
│       ├── data/     // Repositorios y fuentes de datos
│       ├── domain/   // Entidades y casos de uso
│       └── presentation/
│           ├── bloc/ // Manejo de estados y eventos
│           └── views/ // Pantallas y componentes UI
└── main.dart         // Punto de entrada de la aplicación

Dato Técnico: El uso de Bloc permite separar completamente la lógica de negocio de la interfaz de usuario, facilitando las pruebas unitarias y la escalabilidad del sistema.

2. Gestión de Identidad Visual (Tematización)

Para garantizar una experiencia visual coherente con la marca Santa Ana, se ha implementado un sistema de temas centralizado en la clase AppTheme. Esto permite cambiar aspectos visuales de toda la aplicación desde un solo punto.

Misión del Código de Tema

El siguiente fragmento gestiona la transición entre el modo claro y oscuro, definiendo los colores primarios y la tipografía estándar:

// Definición del Tema Global (AppTheme)
static ThemeData get lightTheme {
  return ThemeData(
    useMaterial3: true,
    colorScheme: ColorScheme.fromSeed(
      seedColor: primaryColor,
      primary: primaryColor,
      secondary: accentColor,
    ),
    appBarTheme: const AppBarTheme(
      centerTitle: true,
      elevation: 0,
    ),
  );
}

3. Gestión de Estado con Bloc

La lógica de negocio se maneja mediante eventos y estados. El BlocBloc (u HomeBloc) es el cerebro que recibe acciones del usuario y emite nuevos estados hacia la interfaz.

Misión del Manejo de Estados

Este código asegura que la UI sea reactiva. Cuando ocurre un evento (como pulsar un botón de reporte), el Bloc procesa la información y emite un estado que la pantalla "escucha" para actualizarse:

class BlocBloc extends Bloc<BlocEvent, BlocState> {
  BlocBloc() : super(BlocInitial()) {
    on<BlocEvent>((event, emit) {
      // Aquí se procesa la lógica antes de cambiar la pantalla
      // emit(LoadingState()); -> procesar -> emit(LoadedState());
    });
  }
}
