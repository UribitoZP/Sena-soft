Aplicativo de Escritorio

Guía completa de instalación, configuración y funcionamiento del sistema de gestión hotelera Hotel Santa Ana.

1. Requisitos del Sistema

Antes de ejecutar el aplicativo, asegúrate de tener instalado lo siguiente en tu máquina:

Requisito Versión mínima Notas
JDK (Java Development Kit) 17 o superior Necesario para compilar y ejecutar el proyecto
Sistema Operativo Windows 10/11 El script run.bat es para Windows
Espacio en disco ~50 MB Incluye JARs, binarios y base de datos
Red local (opcional) WiFi o LAN Solo si se usará el aplicativo móvil

Sin base de datos externa: El sistema usa SQLite embebido. No necesitas instalar MySQL, MariaDB ni ningún servidor de base de datos. La base de datos se crea automáticamente al ejecutar por primera vez.

2. Librerías incluidas (carpeta /lib)

El proyecto ya incluye todas las dependencias en la carpeta Aplicativo Escritorio/lib/. No necesitas descargar nada adicional.

Aplicativo Escritorio/
└── lib/
    ├── jcalendar-1.4.jar          // Selector visual de fechas
    ├── sqlite-jdbc-3.45.1.0.jar   // Driver de conexión a SQLite
    ├── slf4j-api-1.7.36.jar       // Interfaz de logging (requerida por SQLite)
    └── slf4j-nop-1.7.36.jar       // Suprime los mensajes de log internos

Instalación y Ejecución

Opción A — Ejecución con run.bat (Recomendada)

Abre el Explorador de archivos, navega a la carpeta Aplicativo Escritorio/ y haz doble clic en run.bat.

El script realiza automáticamente estos pasos:

  1. Crea la carpeta bin/ si no existe.
  2. Compila todos los archivos .java del proyecto incluyendo las librerías.
  3. Copia los recursos gráficos a la carpeta de binarios.
  4. Ejecuta la aplicación.
:: run.bat (simplificado)
javac -cp ".;lib\jcalendar-1.4.jar;lib\sqlite-jdbc-3.45.1.0.jar;..." ^
      -d bin -sourcepath src src\com\santaana\main\ApplicationMain.java ...

java -cp ".;..\lib\jcalendar-1.4.jar;..." com.santaana.main.ApplicationMain

Error de compilación: Si aparece un error, verifica que el JDK esté instalado y que la variable de entorno JAVA_HOME esté configurada. Puedes comprobarlo ejecutando java -version en la terminal.

Opción B — Ejecución Manual desde terminal

# Desde la carpeta "Aplicativo Escritorio/"

# 1. Crear carpeta de binarios
mkdir bin

# 2. Compilar (Windows — usar ; como separador de classpath)
javac -cp ".;lib\jcalendar-1.4.jar;lib\sqlite-jdbc-3.45.1.0.jar;lib\slf4j-api-1.7.36.jar;lib\slf4j-nop-1.7.36.jar" ^
      -d bin -sourcepath src src\com\santaana\main\ApplicationMain.java

# 3. Ejecutar (desde la carpeta bin/)
cd bin
java -cp ".;..\lib\jcalendar-1.4.jar;..\lib\sqlite-jdbc-3.45.1.0.jar;..\lib\slf4j-api-1.7.36.jar;..\lib\slf4j-nop-1.7.36.jar" ^
     com.santaana.main.ApplicationMain

Primera ejecución — ¿Qué pasa automáticamente?

Al iniciar por primera vez, el sistema realiza en orden:

Paso Clase responsable Qué hace
1 SchemaManager Crea el archivo santaana.db y las tablas usuarios, habitaciones y reservas.
2 SeedData Si la base está vacía, inserta 2 usuarios y 6 habitaciones de prueba.
3 RestServer Levanta el servidor HTTP en el puerto 8080 para el aplicativo móvil.
4 LoginFrame Muestra la pantalla de inicio de sesión.

Credenciales de acceso

Usuario Contraseña Rol Acceso
admin 1234 Administrador Tablero, Reservas, Gestión de habitaciones
recepcion 1234 Recepcionista Reservas (sin gestión de habitaciones)

2. Base de Datos SQLite Embebida

A diferencia de sistemas que requieren un servidor de base de datos separado (MySQL, PostgreSQL), este sistema usa SQLite. El archivo de base de datos (santaana.db) vive dentro de la misma carpeta del proyecto y no requiere ningún proceso externo corriendo.

¿Por qué SQLite?

  • Sin instalación: La librería viene incluida en el JAR, no hay que instalar nada.
  • Portabilidad: Toda la información queda en un solo archivo que se puede copiar o respaldar fácilmente.
  • Ideal para un solo equipo: Perfecta para aplicaciones de escritorio de uso local.

Esquema de la base de datos

-- Tabla usuarios
CREATE TABLE usuarios (
    id       INTEGER PRIMARY KEY AUTOINCREMENT,
    nombre   TEXT NOT NULL,
    usuario  TEXT NOT NULL UNIQUE,
    clave    TEXT NOT NULL,
    rol      TEXT NOT NULL CHECK(rol IN ('Administrador','Recepcionista'))
);

-- Tabla habitaciones
CREATE TABLE habitaciones (
    id      INTEGER PRIMARY KEY AUTOINCREMENT,
    numero  TEXT NOT NULL UNIQUE,
    tipo    TEXT NOT NULL,
    precio  REAL NOT NULL,
    estado  TEXT NOT NULL CHECK(estado IN ('Disponible','Ocupada','Limpieza','Mantenimiento'))
);

-- Tabla clientes
CREATE TABLE clientes (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    nombre      TEXT NOT NULL,
    documento   TEXT UNIQUE NOT NULL,
    telefono    TEXT,
    correo      TEXT
);

-- Tabla reservas
CREATE TABLE reservas (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    id_habitacion   INTEGER NOT NULL REFERENCES habitaciones(id),
    id_usuario      INTEGER NOT NULL REFERENCES usuarios(id),
    id_cliente      INTEGER NOT NULL REFERENCES clientes(id),
    fecha_entrada   TEXT NOT NULL,
    hora_entrada    TEXT DEFAULT '12:00',
    fecha_salida    TEXT NOT NULL,
    hora_salida     TEXT DEFAULT '12:00',
    tipo_estadia    TEXT DEFAULT 'Noche',
    anticipo        REAL DEFAULT 0,
    estado          TEXT NOT NULL CHECK(estado IN ('Activa','Completada','Cancelada'))
);

-- Tabla historial
CREATE TABLE historial (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    tipo        TEXT NOT NULL,
    titulo      TEXT NOT NULL,
    descripcion TEXT NOT NULL,
    fecha_hora  TEXT NOT NULL DEFAULT (datetime('now','localtime')),
    id_usuario  INTEGER DEFAULT 0
);

-- Tabla cierres_mes
CREATE TABLE cierres_mes (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    mes              TEXT NOT NULL UNIQUE,
    id_usuario       INTEGER NOT NULL REFERENCES usuarios(id),
    fecha_cierre     TEXT NOT NULL DEFAULT (datetime('now','localtime')),
    total_ingresos   REAL NOT NULL DEFAULT 0,
    total_reservas   INTEGER NOT NULL DEFAULT 0,
    total_completadas INTEGER NOT NULL DEFAULT 0,
    total_canceladas INTEGER NOT NULL DEFAULT 0,
    notas            TEXT DEFAULT ''
);

3. Patrón DAO (Data Access Object)

Cada entidad del sistema tiene su propio DAO que centraliza todas las consultas SQL. Las vistas nunca acceden directamente a la base de datos — siempre lo hacen a través del DAO correspondiente.

DAO Métodos principales
HabitacionDAO listarTodas(), listarDisponiblesEnFechas(desde, hasta), actualizarEstado(id, estado), actualizarDatos(id, tipo, precio), agregar(), eliminar()
ReservaDAO listarTodas(), crear(idHab, idUsuario, nombre, doc, tel, correo, entrada, horaEnt, salida, horaSal, tipo, anticipo), actualizarEstado(id, estado)
ClienteDAO buscarPorDocumento(doc), crear(cliente), actualizar(cliente), listarTodos()
UsuarioDAO autenticar(usuario, clave, rol), autenticarSinRol(usuario, clave)
CierreMesDAO esCerrado(mes), cerrarMes(mes, idUsuario, notas), listarCierres()
ReporteDAO getTotalIngresos(), getTotalAnticipos(), getTotalReservas(), getReservasPorEstado(), getIngresosPorMes()

4. Ciclo de vida de una habitación

El sistema controla los estados de las habitaciones con el siguiente flujo obligatorio:

Disponible  ──[Nueva reserva]──►  Ocupada
Ocupada     ──[Checkout]────────►  Limpieza
Limpieza    ──[Habilitar]────────►  Disponible

Cualquier estado  ──[Gestión]──►  Mantenimiento
Mantenimiento     ──[Gestión]──►  Disponible

5. Servidor REST integrado

Al iniciar el aplicativo, se levanta automáticamente un servidor HTTP en el puerto 8080 usando la librería com.sun.net.httpserver incluida en el JDK (sin dependencias externas). Este servidor expone los datos de solo lectura para el aplicativo móvil.

Endpoint Método Descripción
/auth/login POST Autentica usuario. Recibe {"usuario":"...","clave":"..."}
/habitaciones GET Retorna todas las habitaciones con id, numero, tipo, precio y estado
/reservas GET Retorna todas las reservas con datos del cliente y número de habitación
/stats GET Retorna conteos agrupados de habitaciones y reservas por estado

Seguridad: El servidor solo escucha en la red local. Todos los endpoints incluyen el header Access-Control-Allow-Origin: * para permitir conexiones desde la app móvil.

Arquitectura actual — Modo de pruebas: Actualmente el servidor REST se ejecuta en el mismo PC que el aplicativo de escritorio. Esta configuración fue adoptada para pruebas de conexión y evidencia del proyecto académico.

En una etapa próxima, el servidor será migrado a un equipo dedicado (PC adaptado para servidor) que estará encendido de forma permanente. De esta manera la app móvil podrá consultar los datos en cualquier momento sin depender de que el escritorio esté abierto.

6. Personalización: Modo Oscuro "Dark Blue"

El sistema incluye un alternador de tema claro/oscuro implementado con el patrón Observer.

  • ThemeManager: Clase central que almacena el tema activo y notifica a todos los oyentes registrados.
  • ThemeListener: Interfaz que implementa cada ventana para recibir actualizaciones en tiempo real.

Solución de Problemas Comunes

Error Causa Solución
java: command not found JDK no instalado o no en PATH Instalar JDK 17+ y agregar JAVA_HOME a las variables de entorno
NoClassDefFoundError: org/slf4j/LoggerFactory Faltan los JARs de SLF4J en el classpath Verificar que slf4j-api-1.7.36.jar y slf4j-nop-1.7.36.jar estén en /lib
[SQLITE_CONSTRAINT_CHECK] Valor inválido para una columna con restricción CHECK Verificar que el estado sea exactamente: Disponible, Ocupada, Limpieza o Mantenimiento
Puerto 8080 ocupado Otro proceso usa el puerto 8080 Ejecutar netstat -ano | findstr :8080 para identificar el proceso y cerrarlo
Datos no se actualizan en pantalla El panel no se refresca después de una acción Usar el botón de recarga o cerrar y reabrir la sección. El sistema usa SwingUtilities.invokeLater() para refrescos seguros.
