Aplicativo de Escritorio

Arquitectura Modular Orientada a Roles (Java Swing)

1. Control de "Código Espagueti"

Para evitar que el código se vuelva inmanejable a medida que el sistema crece, hemos implementado una estructura de paquetes basada en el principio de responsabilidad única. Cada rol (Administrador y Recepcionista) tiene su propio espacio de trabajo dentro del proyecto:

com.santaana
├── controller
│   ├── admin         // Gestión lógica para el Administrador
│   └── receptionist  // Gestión lógica para el Recepcionista
├── model             // Clases de datos (Entidades)
└── view
    ├── admin         // Interfaces exclusivas: Usuarios, Configuración, Reportes
    ├── receptionist  // Interfaces exclusivas: Reservas, Facturación
    └── components    // Elementos UI reutilizables (Botones, logos personalizados)

Ventaja: Esta estructura permite que los desarrolladores trabajen en módulos independientes sin generar conflictos en las clases principales.

2. Orquestación Dinámica

El sistema utiliza una ventana principal (HomeFrame) que actúa como un contenedor dinámico. En lugar de tener múltiples ventanas abiertas, el sistema inyecta el panel correspondiente según el rol del usuario autenticado.

Componente Responsabilidad Estado
AdminDashboard Panel de control para reportes y gestión global. Estructurado
ReceptionistPanel Gestión operativa de huéspedes y habitaciones. Estructurado
HomeFrame Contenedor base y manejo de sesión. Optimizado

Estándar de Desarrollo: Queda prohibido escribir lógica de negocio o consultas a base de datos dentro de los archivos de vista. Todo debe pasar a través de sus respectivos controladores.
