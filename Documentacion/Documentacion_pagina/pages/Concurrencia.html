Concurrencia

Manejo de hilos, sincronización de conexiones y resolución de condiciones de carrera.

1. Entorno Multihilo

La aplicación funciona en un entorno multihilo real con dos fuentes de concurrencia:

  • EDT (Event Dispatch Thread): Hilo principal de Java Swing que maneja la interfaz gráfica y responde a eventos del usuario.
  • Servidor REST: Se ejecuta en su propio hilo (Executors.newSingleThreadExecutor()) para atender peticiones HTTP del aplicativo móvil.

Ambos hilos pueden solicitar una conexión a la base de datos simultáneamente.

2. Thread Safety — synchronized

Para evitar condiciones de carrera al crear la conexión SQLite, DatabaseConnection.getConnection() se marcó como synchronized. Esto garantiza que si el EDT y el servidor REST llaman al método al mismo tiempo mientras la instancia es null, solo un hilo ejecuta la inicialización. El otro hilo espera y obtiene la misma instancia ya creada.

public static synchronized Connection getConnection() throws SQLException {
    if (instance == null || instance.isClosed()) {
        Class.forName("org.sqlite.JDBC");
        instance = DriverManager.getConnection(DB_URL);
        instance.setAutoCommit(true);
    }
    return instance;
}

El synchronized solo afecta el rendimiento durante la inicialización. Una vez creada la conexión, el bloqueo es prácticamente instantáneo (solo lectura de referencia).

3. Ruta Absoluta de Base de Datos

Otro problema de concurrencia indirecto: si el usuario ejecutaba la aplicación desde un acceso directo en el Escritorio, el directorio de trabajo cambiaba y SQLite creaba un archivo santaana.db vacío en el Escritorio, mientras el servidor REST y la UI apuntaban a bases de datos diferentes.

La solución calcula la ruta absoluta usando ProtectionDomain.getCodeSource().getLocation(), asegurando que sin importar desde dónde se ejecute el proceso, la base de datos siempre se busque y cree en la carpeta raíz del proyecto.

private static String inicializarDbUrl() {
    File dirClases = new File(
        DatabaseConnection.class
            .getProtectionDomain().getCodeSource().getLocation()
            .toURI()
    ).getAbsoluteFile();

    File dbFile = dirClases.isDirectory()
        && dirClases.getName().equalsIgnoreCase("bin")
        ? new File(dirClases.getParentFile(), "santaana.db")
        : new File(dirClases.getParentFile(), "santaana.db");

    return "jdbc:sqlite:" + dbFile.getAbsolutePath();
}

4. Manejo Global de Excepciones

ApplicationMain registra un manejador global de excepciones no capturadas en el EDT mediante SwingUtilities.invokeLater(), asegurando que cualquier error inesperado en la interfaz gráfica se muestre al usuario y no pase desapercibido en la consola.
