Seguridad

Medidas implementadas para proteger contraseñas, datos sensibles y el acceso a la API REST.

1. Hash de Contraseñas — PBKDF2

Las contraseñas ya no se almacenan en texto plano. PasswordUtil aplica PBKDF2WithHmacSHA256 con 600.000 iteraciones y sal aleatoria de 16 bytes, usando solo el JDK estándar (javax.crypto.SecretKeyFactory), sin dependencias externas.

private static final String ALGORITHM = "PBKDF2WithHmacSHA256";
private static final int ITERATIONS = 600_000;
private static final int KEY_LENGTH = 256;
private static final int SALT_LENGTH = 16;

public static String hash(String password) {
    byte[] salt = SecureRandom.getSeed(SALT_LENGTH);
    SecretKeyFactory skf = SecretKeyFactory.getInstance(ALGORITHM);
    PBEKeySpec spec = new PBEKeySpec(password.toCharArray(), salt, ITERATIONS, KEY_LENGTH);
    byte[] hash = skf.generateSecret(spec).getEncoded();
    return Base64.getEncoder().encodeToString(salt) + ":" + Base64.getEncoder().encodeToString(hash);
}

Migración automática: El SchemaManager versión 7 migra las contraseñas en texto plano existentes a hash PBKDF2 al iniciar la aplicación. No requiere intervención manual.

2. Autenticación por Token

El servidor REST genera un token UUID tras un login exitoso. Todos los endpoints protegidos requieren el header Authorization: Bearer <token>. TokenManager almacena los tokens activos en memoria y los invalida al cerrar la aplicación.

3. Rate Limiting

5 intentos fallidos de login desde la misma IP producen un bloqueo de 30 segundos, evitando ataques de fuerza bruta. Cada intento fallido (tanto desde la API REST como desde la UI de escritorio) se persiste en la tabla historial con tipo "Login", permitiendo su consulta posterior en el panel de Historial.

4. Contraseñas en Memoria

Los campos de contraseña en la interfaz gráfica se limpian explícitamente después de usar (clearPassword()). En el diálogo de edición de usuarios, el campo de contraseña no se pre-rellena, evitando que el hash quede visible o que se reenvíe accidentalmente.

5. Base de datos excluida de Git

El archivo santaana.db fue eliminado del repositorio y agregado a .gitignore mediante los patrones bin/ y *.db. Esto evita que datos de prueba o reales queden expuestos en el control de versiones.

6. TLS/SSL

El servidor REST embebido utiliza HttpsServer con cifrado TLS. El keystore autofirmado (ssl/keystore.p12) se carga mediante ProtectionDomain para localizar la ruta absoluta, y se configura un SSLContext con algoritmo TLS y KeyManagerFactory SunX509.

  • Puerto: 8443
  • Keystore: ssl/keystore.p12 (PKCS12)
  • Algoritmo: RSA 2048 bits con firma SHA384
  • Validez: 365 días

7. Pendientes

  • Parser JSON: AuthHandler.extraer() usa un parser manual. Se recomienda migrar a org.json o Gson.
