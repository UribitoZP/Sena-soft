API REST

Servidor HTTP integrado para la integración con el aplicativo móvil.

1. Servidor Embebido

Al iniciar el aplicativo, se levanta automáticamente un servidor HTTP en el puerto 8080 usando la librería com.sun.net.httpserver incluida en el JDK (sin dependencias externas).

2. Endpoints

Endpoint Método Autenticación Descripción
/auth/login POST Público Recibe {"usuario":"...","clave":"..."}, retorna token de acceso
/habitaciones GET Bearer token Retorna todas las habitaciones con id, numero, tipo, precio y estado
/reservas GET Bearer token Retorna todas las reservas con datos del cliente y número de habitación
/stats GET Bearer token Retorna conteos agrupados de habitaciones y reservas por estado

3. Autenticación

Todos los endpoints (excepto /auth/login) requieren el header Authorization: Bearer <token>. El token es un UUID generado por TokenManager al autenticarse exitosamente.

Ejemplo de login

POST /auth/login
Content-Type: application/json

{"usuario":"admin","clave":"1234"}

// Respuesta exitosa (200):
{"token":"a1b2c3d4-...","usuario":"admin","rol":"Administrador"}

// Error (401):
{"error":"Credenciales inválidas"}

Ejemplo de consulta protegida

GET /habitaciones
Authorization: Bearer a1b2c3d4-...

// Respuesta (200):
[{"id":1,"numero":"101","tipo":"Estandar","precio":80000,"estado":"Disponible"},...]

// Token inválido (401):
{"error":"Token inválido"}

4. Rate Limiting

AuthHandler implementa un contador de intentos por dirección IP:

  • Después de 5 intentos fallidos consecutivos, la IP queda bloqueada.
  • El bloqueo dura 30 segundos.
  • Los intentos fallidos se registran automáticamente en el historial del sistema.

5. CORS

El servidor incluye la cabecera Access-Control-Allow-Origin: * para permitir conexiones desde el aplicativo móvil. Las peticiones OPTIONS (preflight) se manejan correctamente.

6. Manejo de errores

Si ocurre un error de base de datos, el servidor retorna {"error":"Error interno del servidor"} con código 500, sin exponer detalles técnicos al cliente.

Seguridad: El servidor solo escucha en la red local. Todos los endpoints protegidos requieren token válido.

Arquitectura actual — Modo de pruebas: Actualmente el servidor REST se ejecuta en el mismo PC que el aplicativo de escritorio. En una etapa próxima, el servidor será migrado a un equipo dedicado que estará encendido de forma permanente.
