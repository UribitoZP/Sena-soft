Base de Datos SQLite

Esquema completo, sistema de migraciones y datos iniciales del sistema hotelero.

1. SQLite Embebido

A diferencia de sistemas que requieren un servidor de base de datos separado (MySQL, PostgreSQL), este sistema usa SQLite. El archivo de base de datos (santaana.db) se almacena en la raíz del proyecto y no requiere ningún proceso externo corriendo.

  • Sin instalación: La librería viene incluida en el JAR, no hay que instalar nada.
  • Portabilidad: Toda la información queda en un solo archivo que se puede copiar o respaldar fácilmente.
  • Ideal para un solo equipo: Perfecta para aplicaciones de escritorio de uso local.

2. Esquema de la base de datos

-- Tabla usuarios
CREATE TABLE usuarios (
    id       INTEGER PRIMARY KEY AUTOINCREMENT,
    nombre   TEXT NOT NULL,
    usuario  TEXT NOT NULL UNIQUE,
    clave    TEXT NOT NULL,
    rol      TEXT NOT NULL CHECK(rol IN ('Administrador','Recepcionista'))
);

-- Tabla habitaciones
CREATE TABLE habitaciones (
    id      INTEGER PRIMARY KEY AUTOINCREMENT,
    numero  TEXT NOT NULL UNIQUE,
    tipo    TEXT NOT NULL,
    precio  REAL NOT NULL,
    estado  TEXT NOT NULL CHECK(estado IN ('Disponible','Ocupada','Limpieza','Mantenimiento'))
);

-- Tabla clientes
CREATE TABLE clientes (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    nombre      TEXT NOT NULL,
    documento   TEXT UNIQUE NOT NULL,
    telefono    TEXT,
    correo      TEXT
);

-- Tabla reservas
CREATE TABLE reservas (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    id_habitacion   INTEGER NOT NULL REFERENCES habitaciones(id),
    id_usuario      INTEGER NOT NULL REFERENCES usuarios(id),
    id_cliente      INTEGER NOT NULL REFERENCES clientes(id),
    fecha_entrada   TEXT NOT NULL,
    hora_entrada    TEXT DEFAULT '12:00',
    fecha_salida    TEXT NOT NULL,
    hora_salida     TEXT DEFAULT '12:00',
    tipo_estadia    TEXT DEFAULT 'Noche',
    anticipo        REAL DEFAULT 0,
    estado          TEXT NOT NULL CHECK(estado IN ('Activa','Completada','Cancelada'))
);

-- Tabla historial
CREATE TABLE historial (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    tipo        TEXT NOT NULL,
    titulo      TEXT NOT NULL,
    descripcion TEXT NOT NULL,
    fecha_hora  TEXT NOT NULL DEFAULT (datetime('now','localtime')),
    id_usuario  INTEGER DEFAULT 0
);

-- Tabla cierres_mes
CREATE TABLE cierres_mes (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    mes              TEXT NOT NULL UNIQUE,
    id_usuario       INTEGER NOT NULL REFERENCES usuarios(id),
    fecha_cierre     TEXT NOT NULL DEFAULT (datetime('now','localtime')),
    total_ingresos   REAL NOT NULL DEFAULT 0,
    total_reservas   INTEGER NOT NULL DEFAULT 0,
    total_completadas INTEGER NOT NULL DEFAULT 0,
    total_canceladas INTEGER NOT NULL DEFAULT 0,
    notas            TEXT DEFAULT ''
);

3. Sistema de Migraciones (SchemaManager)

El sistema usa PRAGMA user_version de SQLite para versionar el esquema y aplicar migraciones automáticas al arrancar. Cada versión incrementa el número y ejecuta los cambios necesarios.

Versión Cambio
v1Esquema inicial: usuarios, habitaciones, reservas, historial
v2Columna correo en usuarios
v3Columna id_cliente en reservas
v4Columnas hora y tipo_estadia en reservas
v5Columna anticipo en reservas
v6Tabla clientes creada y reservas normalizada
v7Migración de contraseñas planas a hash PBKDF2

4. Datos Iniciales (SeedData)

Al iniciar con la base de datos vacía, SeedData inserta:

  • 2 usuarios: admin y recepcion con contraseñas hasheadas con PBKDF2.
  • 15 habitaciones: de distintos tipos y precios, todas en estado Disponible.
